## 结论

- SQL 结果答对 9/10 题，结果准确率 90%。这里的分母是本次固定的 10 道题，不代表所有新问题的通用准确率。
- 首次生成 SQL 执行成功 9/10 题，SQL 成功率 90%。
- WebSocket 完整结束 10/10 题，无连接超时；第 10 题虽然正常结束，但 SQL 返回状态码 500，因此不能算查询成功。
- 平均总耗时 49.571 秒/题，中位数 48.954 秒/题，最快 39.292 秒，最慢 66.176 秒。
- 平均 11.638 秒收到首个流程事件，平均 32.256 秒完成选表，平均 41.012 秒生成 SQL，平均 43.593 秒收到 SQL 结果。
- 10 道题合计使用 371,907 个模型 token，其中输入 354,897 个、输出 17,010 个；平均 37,190.7 个/题。

判分口径：公司、指标、报告期或交易日期必须正确；数值允许千分位、尾零、保留两位小数及元/万元/亿元的等价换算。SQL 成功但答非所问仍判错。

## SQL 检查

前 9 题生成的 SQL 都命中了能返回正确数值的表，并且日期、公司及指标条件正确。完整 SQL 位于原始结果的每题 `by_type["1007"]` 中。

第 10 题错误 SQL 的关键部分是：

```sql
FROM DERI_STK_AH_PRC A
JOIN GET_A_INDUSTRY B ON A.COMCODE = B.COMCODE
WHERE B.SEC_SNAME LIKE '%贵州茅台%'
  AND A.TRADEDATE >= '2026-08-01 00:00:00'
  AND A.TRADEDATE < '2026-09-01 00:00:00'
ORDER BY A.A_PRC DESC, A.TRADEDATE ASC
LIMIT 1
```

这条 SQL 选择了 A/H 股价格衍生表，执行后没有数据。正确查询应使用日行情表 `STK_MKT`，按贵州茅台的 `INNER_CODE` 和 2026 年 8 月日期范围过滤，再按 `TCLOSE DESC, TRADEDATE ASC` 排序。标准结果是 2026-08-03 的 1,358.98 元。

此外，第 10 题在 SQL 状态码为 500、结果明确为空后，最终解释仍写了“查询结果符合要求”。这属于失败状态传递问题，不能只通过改元数据解决。
